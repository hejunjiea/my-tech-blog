# 我的技术博客 · 服务器部署完整操作文档

> 适用版本：blog-site 当前版本（零依赖 Node.js 20 服务 + 静态页面 + 口令写作接口）
> 目标读者：拿到 `blog-deploy.tar.gz` 后，需要从零部署到一台 Linux 服务器的人

---

## 1. 架构与运行要素

```
浏览器 ──HTTPS──> Nginx ──HTTP──> Node 服务 (8000)
                                    ├── public/  静态页面（HTML/CSS/JS/posts.json）
                                    ├── seed.json 随包发布的基线文章
                                    └── DATA_DIR/posts.json 线上新写/修改的文章
```

| 要素 | 值 |
|---|---|
| 运行时 | Node.js >= 20（无第三方依赖，不需要 npm install） |
| 默认端口 | 8000（读 `PORT`） |
| 监听地址 | 0.0.0.0（读 `HOST`） |
| 数据目录 | `DATA_DIR`，默认 `/tmp/blog-data`（**生产必须改**） |
| 写作口令 | `ADMIN_TOKEN`，必填 |
| 主要接口 | `GET /api/posts`、`POST /api/posts`、`DELETE /api/posts/:slug` |

两条必须记住的规则：

1. `DATA_DIR` 必须落在持久磁盘或挂载卷上，否则重新部署/重建容器会清空线上文章。
2. 只备份 `DATA_DIR/posts.json` 就能保住所有线上文章。

## 2. 准备工作

### 2.1 服务器

- 最低配置：1 核 / 1 GB 内存 / 10 GB 磁盘
- 系统建议：Ubuntu 22.04 或 Debian 12（示例命令基于此）
- 常见选择：云厂商轻量应用服务器、VPS、内网 NAS、家里的旧电脑装 Linux

### 2.2 域名（可选但强烈建议）

- 解析 `A` 记录到服务器公网 IP，例如 `blog.example.com`
- 有域名才能申请免费 HTTPS 证书（下文用 Let's Encrypt）
- 没有域名也能用 `http://IP:8000` 访问，但口令是明文传输，不建议长期这样用

### 2.3 开放端口

- 有域名 + Nginx：只开放 `22`（SSH）、`80`、`443`
- 直连 Node：额外开放 `8000`（或在云厂商安全组放行）

```sh
# Ubuntu 使用 ufw 的示例
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

## 3. 上传部署包

在**本地电脑**执行（把 `user`、`服务器IP` 换成实际值）：

```sh
scp blog-deploy.tar.gz user@服务器IP:~/
```

登录服务器并解压：

```sh
ssh user@服务器IP
mkdir -p ~/blog && tar -xzf ~/blog-deploy.tar.gz -C ~/blog --strip-components=1
cd ~/blog
ls        # 应看到 app/ Dockerfile docker-compose.yml start.sh nginx.conf.example .env.example README.md
```

准备配置：

```sh
cp .env.example .env
vim .env
```

`.env` 最少修改两处：

```ini
ADMIN_TOKEN=换成一串 12 位以上的随机口令
DATA_DIR=~/blog/data
```

生成随机口令的简便方法：

```sh
openssl rand -base64 12
```

## 4. 方案 A：Docker 部署（推荐）

### 4.1 安装 Docker

```sh
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
docker compose version     # 确认 compose 插件可用
```

### 4.2 启动

```sh
cd ~/blog
sudo docker compose up -d --build
sudo docker compose ps        # 状态应为 running
sudo docker compose logs -f   # 看到 "blog server listening on 0.0.0.0:8000" 即成功
```

说明：

- `docker-compose.yml` 已把宿主机 `./data` 挂到容器 `/data`，删容器不丢文章
- `restart: unless-stopped` 已配置，服务器重启后自动拉起
- 端口默认映射 `8000:8000`

### 4.3 常用运维命令

```sh
sudo docker compose restart      # 重启
sudo docker compose down         # 停止并删除容器（数据仍在 ./data）
sudo docker compose up -d        # 重新启动
sudo docker compose pull  # 仅当使用镜像仓库时
```

## 5. 方案 B：Node + systemd（不用 Docker）

### 5.1 安装 Node.js 20

```sh
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v    # 应输出 v20.x
```

### 5.2 先手动试运行

```sh
cd ~/blog
sh start.sh
```

看到 `启动：http://0.0.0.0:8000` 后，另开终端 `curl -I http://127.0.0.1:8000`，返回 200 即正常，`Ctrl+C` 停止。

### 5.3 注册为系统服务

创建 `/etc/systemd/system/blog.service`：

```ini
[Unit]
Description=My Tech Blog
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/home/USERNAME/blog
EnvironmentFile=/home/USERNAME/blog/.env
ExecStart=/usr/bin/node /home/USERNAME/blog/app/server.js
Restart=always
RestartSec=3
# 只读保护系统目录，数据目录需可写
ReadWritePaths=/home/USERNAME/blog/data
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

把 `USERNAME` 换成你的登录用户；如果目录在 `/home` 下，注意 `User` 与目录属主一致：

```sh
sudo chown -R www-data:www-data /home/USERNAME/blog/data
sudo systemctl daemon-reload
sudo systemctl enable --now blog
sudo systemctl status blog --no-pager
```

常用命令：

```sh
sudo systemctl restart blog
sudo systemctl stop blog
sudo journalctl -u blog -n 100 --no-pager
```

## 6. Nginx 反向代理 + HTTPS

### 6.1 安装并配置

```sh
sudo apt-get install -y nginx
sudo cp ~/blog/nginx.conf.example /etc/nginx/conf.d/blog.conf
sudo vim /etc/nginx/conf.d/blog.conf   # 把 blog.example.com 换成你的域名
```

如果想先用 HTTP 跑通，可临时只保留一个 `listen 80` 的 server 块：

```nginx
server {
    listen 80;
    server_name blog.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

检查并重载：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

### 6.2 申请证书

```sh
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d blog.example.com
```

按提示填写邮箱、同意协议，选择自动跳转 HTTPS。之后 `https://blog.example.com` 即可访问。

证书自动续期由 certbot 定时任务负责，可用下面命令验证：

```sh
sudo certbot renew --dry-run
```

### 6.3 Caddy 替代方案（更省事）

```sh
sudo apt-get install -y caddy
```

`/etc/caddy/Caddyfile`：

```
blog.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

```sh
sudo systemctl reload caddy
```

Caddy 会自动申请并续期证书。

## 8. 数据备份与恢复

### 8.1 备份

```sh
# 手动备份
cp "$DATA_DIR/posts.json" ~/blog-backup-$(date +%F).json

# 每日自动备份（保留 14 天）
crontab -e
```

加入一行（把路径替换成实际值）：

```
0 3 * * * cp /home/USERNAME/blog/data/posts.json /home/USERNAME/backup/posts-$(date +\%F).json && find /home/USERNAME/backup -name 'posts-*.json' -mtime +14 -delete
```

### 8.2 恢复

```sh
sudo systemctl stop blog          # 或 docker compose down
cp ~/blog-backup-2026-11-25.json "$DATA_DIR/posts.json"
sudo systemctl start blog
```

### 8.3 迁移到新服务器

1. 老机器拷出 `DATA_DIR/posts.json`
2. 新机器部署同一部署包
3. 把 `posts.json` 放进新机器的 `DATA_DIR`
4. 启动服务，打开首页核对文章数量

## 9. 更新发布流程

### 9.1 只新增文章（最常用）

两种方式任选：

- **线上写作台**：打开 `/write.html`，口令发布，立即生效，无需重启
- **本地内容库**：把 `.md` 放进 `content/posts`，重新执行 `sh package-deploy.sh` 生成新包，替换服务器上的 `app/` 目录后重启服务

替换时**不要动 `DATA_DIR`**，用户文章与基线文章会自动合并。

### 9.2 更新页面/样式/脚本

1. 本地改 `blog-site/site/` 下的文件
2. `sh package-deploy.sh`
3. 上传新包，替换 `app/`
4. `sudo docker compose up -d --build` 或 `sudo systemctl restart blog`

### 9.3 回滚

保留上一版 `app/` 目录备份即可：

```sh
mv app app.bak && mv app.previous app
sudo systemctl restart blog
```

## 10. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开，`curl 127.0.0.1:8000` 也不通 | 服务没起来 | `journalctl -u blog -n 50` 或 `docker compose logs` 看报错 |
| 浏览器打不开但本机 `curl` 正常 | 防火墙/安全组未放行 | 放行 80/443；直连模式放行 8000 |
| 502 Bad Gateway | Nginx 正常但 Node 挂了 | 先修 Node 服务，再查 `proxy_pass` 端口是否 8000 |
| 发布提示「口令不正确」 | `ADMIN_TOKEN` 与页面填写不一致 | 核对 `.env`，改完重启服务 |
| 发布成功但刷新后消失 | `DATA_DIR` 不可写或指向临时目录 | 改成持久路径，确认属主可写，重启 |
| 首页显示「文章数据加载失败」 | `/api/posts` 或 `posts.json` 404 | 确认 `app/public/posts.json` 存在，服务正常 |
| 重启后新文章全没了 | 数据目录随容器/临时目录被清 | 检查卷挂载与 `DATA_DIR`，从备份恢复 |
| 中文乱码 | 反向代理未透传编码 | 由服务端 `charset=utf-8` 保证，一般无需处理；检查是否被 CDN 改写 |
| certbot 申请失败 | 80 端口未开放或域名未解析 | 先 `curl -I http://域名`，确认解析与放行 |

查看服务日志：

```sh
sudo journalctl -u blog -f            # systemd 方式
sudo docker compose logs -f --tail=100 # Docker 方式
```

## 11. 安全加固建议

- `ADMIN_TOKEN` 至少 12 位，含大小写与数字，不要复用其他密码
- 全站强制 HTTPS，避免口令明文传输
- 不在公网暴露 8000 端口（走 Nginx 反代后关闭安全组 8000）
- `.env` 权限设为 `600`：`chmod 600 .env`
- 定期更新系统与 Node 镜像：`sudo apt update && sudo apt upgrade -y`
- 部署包、`data/posts.json` 不要提交到公开仓库
- 若需多人写作，建议在 Nginx 层为 `/write.html` 与 `/api/` 再加一层 Basic Auth

## 12. 附录

### 12.1 环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `ADMIN_TOKEN` | 写作口令（必填） | 无 |
| `PORT` | 监听端口 | 8000 |
| `HOST` | 监听地址 | 0.0.0.0 |
| `DATA_DIR` | 线上文章存储目录 | `/tmp/blog-data` |

### 12.2 接口

```sh
# 读取全部文章
curl -s https://域名/api/posts

# 发布或覆盖（slug 相同即覆盖）
curl -s -X POST https://域名/api/posts \
  -H 'content-type: application/json' \
  -H 'x-admin-token: 你的口令' \
  -d '{"title":"标题","date":"2026-11-25","category":"笔记","summary":"摘要","content":"## 正文\n\n内容"}'

# 删除（基线文章会被隐藏，不会删除源文件）
curl -s -X DELETE https://域名/api/posts/文章slug -H 'x-admin-token: 你的口令'
```

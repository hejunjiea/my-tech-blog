写下 `%hook` 的那一刻，我们对系统说：这个方法以后归我管了。但这句话在运行时到底意味着什么？理解这一点，能解释很多“为什么我的 Hook 没生效”的疑问。

## Objective-C 的消息转发

Objective-C 的方法调用本质上是消息发送。对象收到消息后，会沿着类的方法列表逐级查找实现。如果找不到，就进入消息转发流程。Substrate 正是利用了这套机制里的可拦截点。

方法列表本质上是一组“选择器到函数指针”的映射。替换一个方法，就是在运行时把某个选择器指向的函数指针换掉，同时保留原始指针，以便调用。

## 方法交换的三个关键动作

- 保存原始实现，确保可以调用回原方法
- 注册新的实现，并把它挂到对应的选择器上
- 保证参数与返回值的调用约定一致，否则会在调用时崩溃

> 崩溃大多不是 Hook 写错了，而是签名对不上。参数类型、返回类型、甚至结构体对齐，都会影响调用约定。

## %orig 的意义

`%orig` 代表原始实现。它不是简单地“调用父类”，而是精确地调用被替换前的那个函数。你可以在调用前后插入逻辑，也可以在特定条件下跳过它——后者正是拦截类需求的核心。

```
%hook SomeClass
- (void)doSomething {
    NSLog(@"before");
    %orig;
    NSLog(@"after");
}
%end
```

## 几点实践建议

第一，尽量少改返回值类型；第二，涉及 UI 的改动放回主线程；第三，给日志加统一前缀，方便在设备日志里过滤。做到这三点，调试效率会明显不同。

面对一个符号被剥离、界面陌生的应用，最耗时的往往不是写 Hook，而是找到该 Hook 谁。这篇笔记记录我常用的三条路径，按代价从低到高排列。

## 路径一：从界面文案反查

界面上出现的任何一段文字都可能是突破口。把文案当作字符串搜索，往往能定位到对应的资源文件，进而找到引用它的控制器。这是成本最低的起点，尤其在目标界面有独特文案时格外有效。

## 路径二：从网络请求反推

如果目标功能依赖后端数据，抓包通常比翻代码更快。观察请求与响应的结构，猜出关键字段，再到二进制里搜索字段名，往往能顺利落到具体的类。

- 先看请求路径，通常能反映业务模块
- 再看字段名，它们常常与属性名一致
- 最后把字段名丢进静态分析工具里搜索引用

## 路径三：运行时枚举与插桩

前两条都不奏效时，才动用运行时手段。Frida 可以在进程内枚举类和方法，也可以在关键路径上打点，观察谁被调用。这一步信息量大，但噪声同样大，建议先缩小范围再插桩。

```
Java.perform(function () {
  var classes = Java.enumerateLoadedClassesSync();
  classes.filter(function (n) {
    return n.toLowerCase().indexOf("login") !== -1;
  }).forEach(function (n) { console.log(n); });
});
```

> 插桩不是目的，缩小问题范围才是。每打一个点，都应该能回答一个具体问题。

## 一个常见的误区

很多人在没确认调用链之前就开始写 Hook，结果发现目标方法根本没被调用。更稳妥的顺序是：先用日志确认调用发生，再动手替换实现。顺序反过来，调试成本会成倍增加。

第一次写 Tweak 的时候，我在一个已经废弃的教程里卡了整整两天。问题不在于概念难，而在于工具链的版本、SDK 的路径、签名的细节，任何一环出错都只会换来一句语焉不详的报错。这篇文章把那次踩坑的完整路径整理下来，希望能让后来的人少走一点弯路。

## 一、先明确你要做什么

在安装任何工具之前，先想清楚目标：是给已有 App 注入一段逻辑，还是修改系统行为？是仅在本机验证，还是要发布成 deb 包？目标不同，环境配置的复杂度差别很大。

- 仅在本机验证：Theos + 一条 make package install 即可
- 需要成包分发：还要处理 control、依赖与图标等元信息
- 需要调试：额外准备 lldb 或 Frida 的联调环境

## 二、安装 Theos

Theos 是一套构建工具，本质是帮你把源码编译成 dylib 并打包成 deb。安装本身只有一行命令，但环境变量必须写进 shell 的配置文件，否则新开的终端里 $THEOS 是空的。

```
export THEOS=~/theos
export PATH=$THEOS/bin:$PATH
```

写完之后记得 `source ~/.zshrc`，并新开一个终端确认变量确实生效。这一步看似琐碎，却是后续所有报错的源头之一。

## 三、SDK 与架构

很多人第一次编译失败，是因为 SDK 缺失或者架构不匹配。设备是 arm64，就必须确保编译目标里包含 arm64。用 `make package` 之前，先看一眼 Makefile 里的 ARCHS 是否写对。

> 工具链的问题，九成可以在报错的第一行找到线索。不要急着查论坛，先把第一行读三遍。

## 四、签名与信任

把 deb 安装到设备后，如果插件没有生效，先检查三件事：进程是否被正确注入、签名是否被系统接受、以及是否重启了对应的进程。前两项可以在设备日志里找到明确记录，第三项则常常被忽略。

# 文章写作与本地部署教程

本文说明这个博客的文章怎么改、怎么在本地运行、怎么增删改文章，以及整个项目结构。看完你可以独立完成日常写作和发布。

---

## 一、先分清三类文章

| 类型 | 存放位置 | 是否进 GitHub Pages | 谁来读写 |
| --- | --- | --- | --- |
| 基线文章 | `content/posts/*.md` | 是，构建时编译进静态页 | 你直接编辑文件 |
| 线上 Decap 文章 | `content/posts/*.md`（后台自动提交） | 是，Actions 自动重建 | `/admin/` 登录后写作 |
| 本地服务文章 | `data/posts.json` | 否，只在本地 Node 服务里 | `write.html` 发布/删除 |

服务端合并规则在 `common-server/server.js` 的 `allPosts()`：

1. 先读构建产物 `seed.json`（来自 Markdown）；
2. 再用 `data/posts.json` 里的同名 `slug` 覆盖；
3. 最后按 `deleted` 列表移除。

所以本地服务的优先级是：**本地服务文章 > Markdown 基线 > 已删除清单**。线上 Decap 不参与这套合并，它直接修改 Markdown 文件。

## 二、修改已经发布的文章

### 2.1 文章来自 Markdown（当前 16 篇都属于这种）

1. 打开 `content/posts/` 下对应的 `.md` 文件。
2. 只改正文或标题，**不要改 front matter 里的 `slug`**，改了会被当成一篇新文章。
3. 本地看效果：

```sh
cd /Users/tanyou/Desktop/2Mac_project/md-blog-site
sh local.sh 8000 你的口令
```

4. 浏览器打开 http://localhost:8000 确认。
5. 推送到 GitHub，Pages 会自动重建：

```sh
git add content/posts
git commit -m "docs: 更新文章内容"
git push origin main
```

约一分钟后访问 https://hejunjiea.github.io/my-tech-blog/ 即可看到新内容。

### 2.2 文章是在写作台“发布到线上”产生的（本地 Node 服务）

1. 本地启动服务后打开 http://localhost:8000/write.html
2. 在右侧「线上文章（选中可载入编辑）」下拉里选中要改的文章；
3. 内容会自动载入表单，原标题、日期、分类、摘要、正文都可修改；
4. 点「发布到线上」，同 `slug` 会覆盖更新，不会多出一篇。

### 2.3 一个必须知道的坑

如果某篇基线文章曾在写作台里编辑过，`data/posts.json` 中就有了一份同 `slug` 的副本。之后你**再改 `.md` 不会生效**，因为本地服务数据优先。

解决办法（二选一）：

- 在写作台里选中这篇文章，点「删除选中文章」，然后重新构建；
- 或者手动编辑 `data/posts.json`，把该 slug 从 `posts` 和 `deleted` 两个数组里都删掉。

## 三、本地部署

### 3.1 一键启动（日常使用）

```sh
cd /Users/tanyou/Desktop/2Mac_project/md-blog-site
sh local.sh 8000 你的口令
```

脚本会依次完成：

1. 运行 `node common-build.mjs local-site/public` 构建静态站；
2. 复制 `common-server/` 下的 `server.js` 等文件与构建产物 `seed.json` 到 `local-site/`；
3. 以 `DATA_DIR=data` 启动 Node 服务。

启动后：

- 首页：http://localhost:8000
- 文章页：http://localhost:8000/article.html?slug=ai-agent
- 写作台：http://localhost:8000/write.html
- 本地服务文章数据：`data/posts.json`

`local.sh` 每次都会重建 `local-site`，但不会删除 `data/`，所以本地发布的文章不会丢。

### 3.2 修改本地口令

口令优先级：命令行参数 > 环境变量 > 默认值 `local-dev`。

```sh
sh local.sh 8000 新口令                  # 临时指定
BLOG_ADMIN_TOKEN=新口令 sh local.sh      # 环境变量
```

或修改 `local.sh` 默认值：

```sh
TOKEN="${2:-${BLOG_ADMIN_TOKEN:-新口令}}"
```

改完重启服务；如果写作台仍提示口令错误，在页面重新输入新口令，或清除浏览器 localStorage 的 `blog-admin-token`。

### 3.3 开发模式（改文件自动重建）

```sh
# 终端 1：监听 common-site/ 与 content/，保存即重建
sh local-dev.sh

# 终端 2：启动服务
cd local-site
PORT=8000 HOST=127.0.0.1 DATA_DIR=../data ADMIN_TOKEN=你的口令 node server.js
```

适合频繁调整样式或文章排版时使用。

### 3.4 停止服务

在运行服务的终端按 `Ctrl+C`。

## 四、增、删、改操作对照表

| 操作 | 做法 | 结果 |
| --- | --- | --- |
| 新增（本地服务） | `write.html` 填写后「发布到线上」 | 写入 `data/posts.json` |
| 新增（线上，手动） | 「导出 Markdown」→ 放进 `content/posts/` → 推送 | 成为基线文章，Actions 重建 |
| 新增（线上，在线） | `/admin/` 登录后保存 | 提交到 `content/posts`，Actions 重建 |
| 修改本地服务文章 | `write.html` 载入后重新发布 | 同 `slug` 覆盖 |
| 修改线上文章 | `/admin/` 编辑，或改 md 后推送 | 产生新 commit |
| 删除本地服务文章 | 选中后「删除选中文章」 | slug 进入 `deleted` 列表 |
| 删除线上文章 | `/admin/` 删除，或删除 md 后推送 | 从 Pages 消失 |
| 恢复成 Markdown 版本 | 把 slug 从 `data/posts.json` 的 `posts`、`deleted` 中移除 | 重新显示 `.md` 内容 |

`data/posts.json` 只有两个数组：

```json
{
  "posts": [],
  "deleted": []
}
```

- `posts`：本地服务新增或覆盖的文章；
- `deleted`：被隐藏的 slug（包括基线文章）。

## 五、文章格式

每篇 Markdown 都以下面的 front matter 开头：

```markdown
---
slug: my-first-post
title: 文章标题
date: 2026-11-25
category: 笔记
summary: 一句话摘要，会显示在首页和搜索结果里
---

正文从这里开始，支持 ## 小标题、- 列表、> 引用、代码块、**加粗**、`行内代码` 和图片 `![说明](assets/uploads/demo.png)`。
```

字段规则：

- `slug`：唯一，只能包含字母、数字、点、下划线、短横线；
- `title`：必填；
- `date`：必填，格式 `YYYY-MM-DD`；
- `category`：可选，默认「笔记」；
- `summary`：可选，用于首页摘要和 SEO 描述。

## 六、整个项目结构

```
md-blog-site/                 # 项目根目录：/Users/tanyou/Desktop/2Mac_project/md-blog-site
├── README.md               # 一页上手说明
├── docs/                   # 详细文档（本文件所在目录）
├── content/posts/*.md      # 文章源文件（唯一基线内容，不加前缀）
├── common-site/            # 页面模板与前端脚本（本地/线上共用）
│   ├── index.html          # 首页
│   ├── article.html        # 文章页（含评论区）
│   ├── write.html          # 写作台
│   ├── style.css
│   └── assets/
│       ├── config.js       # API 地址与评论开关
│       └── app.js          # 渲染、搜索、主题、Markdown 解析
├── common-build.mjs        # 构建：md → posts.json / seed.json / sitemap / rss
├── common-server/          # Node 服务代码（本地/线上共用）
│   ├── server.js           # Node 服务：静态文件 + /api/posts
│   ├── run.sh
│   └── package.json
├── data/posts.json         # 本地服务运行数据：本地文章与删除记录（不入库）
│
├── local.sh                # local：本地一键构建 + 启动
├── local-dev.sh            # local：本地监听自动重建
├── local-site/             # local 产物：本地运行目录（不入库）
│
├── web-deploy.sh           # web：发布静态站（Trae 托管）
├── web-deploy-node.sh      # web：发布 Node 服务
├── web-package-deploy.sh   # web：生成服务器部署包
├── web-package/            # web 产物：服务器部署包（不入库）
├── web-assets/             # web：Dockerfile、compose、Nginx、部署文档
├── web-decap-oauth/        # web：Decap CMS 的 GitHub OAuth 代理（Cloudflare Worker）
├── dist/                   # 构建产物：GitHub Pages（不入库）
└── .github/workflows/web-pages.yml  # web：Pages 自动部署
```

数据流：

```
content/posts/*.md
      │ common-build.mjs
      ▼
common-site/* + posts.json + seed.json
      │                    │
      │                    └─► Node 服务：seed + data/posts.json 合并
      ▼
GitHub Pages（访客只读）        /api/posts（可写，口令保护）
                                  ▲
                          写作台 write.html
```

线上写作另走一条链路：`/admin/`（Decap，GitHub 登录）→ 提交 `content/posts` → Actions 重建 → GitHub Pages。

一句话：**Markdown 是基线；访客阅读走 GitHub Pages 静态页；作者写作有两条路：本地 `write.html` 写 `data/posts.json`，或线上 `/admin/` 通过 Decap 直接提交 Markdown。两条路互不同步。**

## 七、线上写作（Decap CMS）

线上地址：https://hejunjiea.github.io/my-tech-blog/admin/

| 项 | 说明 |
|---|---|
| 访客阅读 | 不需要登录，直接看首页和文章页 |
| 作者写作 | 需要 GitHub 登录 |
| 保存结果 | 提交到 `content/posts/`，触发 Actions 重建 |
| 图片 | 上传到 `common-site/assets/uploads/` |

步骤：

1. 打开后台，点「使用 GitHub 登录」
2. 在 GitHub 页面点 **Authorize**
3. 左侧「文章」→ 新建或选中已有文章
4. `Slug` 只能字母、数字、`.`、`_`、`-`，不要改已有文章的 slug
5. 保存后等待 GitHub Actions 成功，线上约 1 分钟更新

注意：线上保存不会写回本地 `data/posts.json`；本地写作也不会自动同步到 GitHub。

## 八、文章评论

评论区使用 giscus，评论数据保存在 GitHub Discussions，不需要额外服务器。

### 8.1 首次启用

1. 在仓库 `hejunjiea/my-tech-blog` 的 Settings → General → Features 中勾选 **Discussions**；
2. 打开 https://github.com/apps/giscus，点击 Install，授权 `hejunjiea/my-tech-blog`；
3. 打开 https://giscus.app/zh-CN，在「仓库」一栏填入 `hejunjiea/my-tech-blog`；
4. 在「Discussion 分类」选择 `Announcements`，页面会自动生成配置；
5. 把页面里的 `data-repo-id` 和 `data-category-id` 填到 `common-site/assets/config.js`：

```js
window.BLOG_GISCUS = {
  repo: 'hejunjiea/my-tech-blog',
  repoId: 'R_kgDOxxxxxxx',
  category: 'Announcements',
  categoryId: 'DIC_kwDOxxxxxxxx'
};
```

6. 重新构建并推送，评论区就会出现在每篇文章底部。

### 8.2 说明

- 每篇文章按 `slug` 对应一个 Discussion，标题就是 slug；
- 访客评论需要登录 GitHub 账号；
- 主题切换时评论区会自动跟随明暗模式；
- `repo` 留空时评论区不显示，不影响构建和阅读。

## 九、常见问题

**Q：修改后刷新页面没变化？**

先确认构建是否成功：`node common-build.mjs dist`。再看浏览器是否缓存，强制刷新（`Cmd+Shift+R`）。

**Q：写作台提示「当前站点为静态托管」？**

`write.html` 是本地 Node 写作台；GitHub Pages 上没有接口，所以会置灰。线上写作请打开 `/admin/` 用 GitHub 登录。

**Q：线上写作需要登录吗？**

访客阅读不需要登录；作者打开 `/admin/` 写作时才需要 GitHub 登录。

**Q：线上文章会不会同步回 GitHub？**

- 本地 `write.html` 发布的文章只保存在 `data/posts.json`，不会同步到 GitHub
- 线上 `/admin/` 通过 Decap 保存的文章会直接提交到 `content/posts/`，本来就在 GitHub 上
- 要让本地文章进入 GitHub，导出 Markdown 后提交推送，或直接用线上后台写作

**Q：备份要保留哪些东西？**

`content/posts/` 下的 Markdown 和 `data/posts.json` 两个都要保留。

**Q：想恢复到干净的初始状态？**

把 `data/posts.json` 改成 `{"posts": [], "deleted": []}`，再重新构建即可。
